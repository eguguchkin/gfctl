# РЕШЕНО/ТЗ (2026-11-20): watch-дашборд gfctl v2 — состав, формулы, TZ

Статус: СПЕЦИФИКАЦИЯ ЗАФИКСИРОВАНА (обсуждение с пользователем; реализация — по GO,
после/параллельно лейаут-миграции).

## Претензии к текущему watch (v1)

1. Полезных данных из hfctl не увидел (GPU power/sclk/busy/VRAM — отсутствовали);
2. то, что видел — работало криво;
3. **температура неправильная**: `read_first_temp` берёт первую попавшуюся `temp*_input`
   без фильтра по карте — на evo/FAEX это CPU `k10temp`/не тот датчик;
4. метрики `/metrics` выводились сырыми кумулятивными счётчиками без обработки.

## Источники v2

- `/metrics` gufo — кумулятивные счётчики `llamacpp:*` (полный список — EXP-007 факт-база):
  prompt_tokens_total, prompt_tokens_cached_total, prompt_seconds_total,
  prompt_tokens_seconds, tokens_predicted_total, tokens_predicted_seconds_total,
  n_tokens_max, kv_cache_usage_ratio, spec_decode_num_accepted_tokens_total,
  spec_decode_num_drafts_total, spec_decode_num_drafts_total, requests_processing,
  requests_deferred (+ гистограммы без `_bucket`);
- `/sys/class/drm/card*` + `hwmon` (код hfctl 1:1), `/proc/meminfo`;
- health-эндпоинт (роут/режим) + лог контейнера (configured).

## Блоки v2

### «Железо» — перенос из hfctl 1:1
GPU (первая карта vendor 0x1002 в /sys/class/drm/card*): `temp_c` = MAX по всем её
`temp1_input`; `sclk_mhz`; `power_w`; `busy_pct` (card*/device/gpu_busy_percent);
VRAM/GTT (байты → GiB). CPU: `Tctl` (k10temp). Цвета: жёлтый 80–89 °C, красный ≥90 °C.

### «Память» — перенос 1:1
RAM MemTotal/MemAvailable (GiB) + VRAM/GTT (GiB), цвет по заполнению.

### «Движок» — вычисляемые из сырых /metrics (кумулятивные счётчики!)

| Показатель | Формула | Единица |
|---|---|---|
| Генерация (средн. накопленная) | tokens_predicted_total / tokens_predicted_seconds_total | ток/с |
| Генерация (последний запрос) | Δtotal/Δseconds последнего done | ток/с |
| Prefill (средн.) | prompt_tokens_total / prompt_tokens_seconds_total | ток/с |
| Кэш-эффект (доля промпта из кэша) | prompt_tokens_cached_total / prompt_tokens_total ×100 | % |
| Спекуляция: принято (выделенная строка) | accepted / drafts ×100 | % |
| Спекуляция: draft (sparkline Δ за тик) | Δspec_decode_num_drafts_total | ток/с |
| KV: заполнение | kv_cache_usage_ratio ×100 | % |
| KV: пик | n_tokens_max | токенов |
| Очередь | requests_processing / requests_deferred | шт |
| Запросы/токены всего | счётчики | шт |
| Роут/режим | health + лог (configured) | — |

Свойства счётчиков: кумулятивные, обновляются ТОЛЬКО на done-событии → накопленные
средние в idle СТАБИЛЬНЫ (не уменьшаются); пока запрос в работе — средняя не учитывает
его (консервативно, как hfctl); Δ за тик = «пульс завершений» (sparkline), не скорость.

### «Скорость»
Дельты счётчиков за тик — sparkline активности (подпись «пульс завершений»).

### «Логи»
`podman logs` БЕЗ `-t` (время есть в строках движка) + TZ-конверсия в слое watch
(UTC → локальный пояс; контейнер не трогаем). Режимы: TUI + plain — оба.

## Реализация

- python-слой (watch v2) — по принципу «python = data-heavy»; shell остаётся
  оркестратором (podman/curl/системные чтения);
- после/параллельно лейаут-миграции (`4.4-layout-python-decision.md`).

## Приёмка

- фикстуры-снапшоты /metrics (стабильные + live-дельты) в батарею;
- живой прогон на машине: модель грузится → счётчики движутся → отображение 200;
- температуры: сверка с `sensors`/hwmon значениями живой машины.
