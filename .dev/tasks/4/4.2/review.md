## Проверка по пунктам ТЗ ревью

1. **п.1 install-probe и идемпотентность** — ✅. Гейт в коде (`lib/commands.sh:500`): probe только при `healthy=0 && лестница ≠ "-" && канона пары пуст` — ровно заявленная скобка. Healthy-повтор → 0 podman run (§40, прежний ассерт, зелёный); повтор с каноном → «probe пропущен», ровно 1 recreate (§43); single — без probe и без журнала (§43). Скобка SPEC §3 «при уже зафиксированном каноне пары или на healthy-повторе — пропускается: идемпотентность» соответствует гейту 1:1 (в обе стороны). Побочный фикс канона (probe > канон пары > поле 4) прежнее поведение не ухудшает: ранее install всегда писал поле 4 — и на healthy-пути без канона пары пишет его же сейчас (задокументировано в limitations). `install_units` (units.sh:65) контейнер не трогает — probe-путь «уже поднят → wait_health без recreate» корректен; отказ wait_health добивает по `set -e`, как и в соседнем recreate-пути (прежний паттерн).
2. **п.4 part>pin, sha-арбитр** — ✅.
