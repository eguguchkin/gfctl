коммент-контрактов функций, батарея зелёная, ни один пункт не меняет
поведение штатных сценариев установки/снятия.

## Пункты

1. **install-probe**: SPEC §3 требует probe-проверку на этапе install
   (см. SPEC §3 и бэклог-заметки STATE). Реализуй минимальный probe
   (что именно — сверяй с SPEC §3 текстом) ИЛИ, если реализация
   перерастает пачку — правь §3 под реальность. Решение задокументируй
   в dev-report.
2. **Хвост лога → журнал probe**: отчёт probe должен дописывать последние
   строки движкового лога в журнал (сейчас обрываются).
3. **Display-имена GGUF-типов + граница RED**: человекочитаемые имена
   квантов в выводе; непригодные типы (ixs на ffn-шардах — F20) — RED,
   пригодные (q4xl) — зелёные. Живая валидация правила была (F20).
4. **part>pin**: докачка не должна перекрывать уже скачанные part-файлы
   (приоритет local part над pin-сверкой).
5. **Убрать лишний аргумент `--check-types`** (дублирующий).
6. **JSON-экранирование** вывода (спецсимволы в именах/путях ломали JSON).
7. **Атрибуция WARN probe_context**: переформулировать «тихое урезание» —
   первопричина была в старом коде диспетчера без bootstrap (F21), не
   в движке. Текст WARN не должен указывать на движок как на виновника.
8. **reuse=none ассерт**: при касании батареи tests/run_checks.sh добавь
   проверку «кэш не переиспользуется, когда reuse=none» (правило STATE).
