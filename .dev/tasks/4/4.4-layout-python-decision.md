# РЕШЕНИЕ (2026-11-19/20): лейаут gfctl — одна папка = git-репо; принцип python/shell

Статус: РЕШЕНО пользователем (обсуждение темы 2 + принцип python). Реализация — после GO.

## Целевой лейаут

`<любой каталог>/` = **корень git-клона gfctl = STACK_DIR = место запуска**. Соглашение для
наших машин: `~/gfctl/`. Пользователь вправе клонировать в любой каталог — диспетчер
работает от местоположения gfctl-файла (не от cwd).

```
~/gfctl/                        # git-клон = стек = запуск (./gfctl из корня)
├── gfctl                       # диспетчер (bash)
├── lib/, tpl/, tests/, .dev/   # код/батарея/борды
├── .gitignore                  # коммичен: игнорит .data/ и logs/
├── .data/                      # ДАННЫЕ сервера (вне git)
│   ├── models/27b/, flash/     # веса (хардлинки/докачка)
│   ├── cache/<профиль>/        # disk-тир разговоров
│   └── logs/                   # логи окон/сервера
└── (install.sh — УПРАЗДНЯЕТСЯ)
```

## Инвариант и исключения

**Инвариант**: всё живёт внутри папки клона. **Исключения** (вне папки, осознанно):

| Что | Где | Судьба при удалении папки |
|---|---|---|
| Юниты systemd user (gfctl-serve, watchdog) | `~/.config/systemd/user/` | снимаются `gfctl off/uninstall`; файл-остаток — руками |
| linger (user-manager) | `/var/lib/systemd/linger/<user>` | остаётся (это не данные gfctl) |
| memlock-limit | `/etc/security/limits.d/99-gfctl-memlock.conf` | останется (создаётся install/use; безвредный хвост) |
| podman-storage (образ+контейнер+слои) | `~/.local/share/containers/` (~4.5 ГБ) | не удаляется автоматически; полный снос: `podman rmi <образ>` |

## Правила

1. **install.sh упраздняется.** Первый запуск `./gfctl use <профиль>`: gfctl сам создаёт
   `.data/`-каркас (каталоги моделей/кэша/логов), проверяет `.gitignore` (`.data/`, `logs/`
   должны быть игнорируемы — иначе warn «git clean -fdx запрещён»), ставит юниты ПОСЛЕ
   первого use (до канона поднимать нечего). Дефолты: `GFCTL_MODELS=$STACK_DIR/.data/models`.
2. **STACK_DIR = каталог gfctl-файла** (`dirname $(readlink -f "$0")`), не cwd — запуск
   работает из любого подкаталога клона.
3. **Юниты — при первом `use`** (после записи канона), не при первом запуске.
4. **`git clean -fd` безопасен** (`.data/`+`logs/` в .gitignore репо). `git clean -fdx` —
   удаляет данные: запрещённая команда, README warning.
5. **Uninstall**: снимает юниты/контейнер/limits.d; `.data/` и образ НЕ удаляет
   (данные/образ дороги; полный снос — руками: папка + `podman rmi`).
6. **Одна инсталляция на пользователя**: второй клон = конфликт имени контейнера `gufo`
   и порта 8080 (документировать в README).
7. **Миграция машин** (FAEX/evo уже в `gfctl-acc`): gufo стоп → `mv gfctl-acc/* ~/gfctl/`
   (модели/кэш — mv, иноды сохраняются) → юниты перерендерятся → healthy. Файлы
   `gfctl-gh`/`gfctl-acc-src` — упразднены (клон = рабочий каталог).

## Принцип python/shell (РЕШЕНО)

- **shell = тонкий оркестратор** (podman/curl/systemd/файлы) — не расширяется;
- **python = всё data-heavy** (уже: agent_check.py, gguf_type_check.py, watch_tui.py,
  smoke_resp.py) — новые фичи data-heavy пишутся ТОЛЬКО на питоне (watch-переделка,
  TZ-конверсия, JSON-выводы, парсеры логов, таблицы пинов → python-модули);
- **полный переход диспетчера на питон — НЕ сейчас**: этап 4 только закрыт на shell
  (батарея 362, живые EXP-приёмки обеих машин) — переписывание обнуляет инвестицию и
  требует новой полной приёмки;
- **триггеры полного перехода (v2-питон, отдельный этап)**: (а) shell-слой регулярно
  рождает дефекты класса «экранирование/word-split/разбор» (счётчик F-записей это
  покажет), (б) появляется фича, которую bash не тянет (структурные конфиги,
  многопрофильная работа, не-Unix цель);
- до того — точечные переводы при касании: таблицы пинов/сетов → python-модуль,
  `status --json` → python-вывод, парсеры логов → python.

## Порядок реализации (после GO)

1. Код: STACK_DIR-детект (dirname gfctl-файла), bootstrap «первого запуска» (каркас
   .data/ + .gitignore-контроль), install.sh удалить, юниты при первом use,
   uninstall-объём (таблица выше).
2. Батарея: переписать пути-ассерты под `.data/` (+ассерты bootstrap/первого запуска).
3. README/AGENTS/EXP-скрипты: новые пути, «git clone → ./gfctl use».
4. Окна миграции FAEX → evo (gufo stop → mv → install-каркас → use → healthy).
5. Пуш — пользователь.
