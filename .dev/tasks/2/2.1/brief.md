# Brief: 2.1 probe-подбор контекста + gfctl bench (мульти-профили в дело)

## Goal (statable, checkable)
В gfctl работают две новые механики этапа 2 (PLAN), обе локально тестируемые:
1. **probe-подбор контекста** для мульти-профилей: `use 27b-multi` /
   `use flash-multi [--sessions N]` при ОТСУТСТВУЮЩЕМ каноне перебирает
   лестницу контекстов из профильной таблицы (поле 8), логируя каждую
   попытку; первая ЗАГРУЗИВШАЯСЯ ступень фиксируется в каноне; повторный
   use использует канон без перебора. `--no-probe` — без перебора (канон
   если есть, иначе последняя/минимальная ступень таблицы) с WARN.
   Отказ ступени = load_failed/admission-отказ в логе → следующая ступень
   (пауза F10 между recreate); все ступени отказали → die с цифрами всех
   попыток.
2. **`gfctl bench`**: фикстура merge_sort (`tpl/bench/…`, md5 253c7ac5,
   НЕ редактировать) ×3 прогона по HTTP: wall + decode tok/s каждого
   прогона + сводка. Работает на живом сервере; при мёртвом порте —
   внятный отказ.
3. Канон per (профиль × sessions): context фиксируется для пары
   (профиль, sessions) — переключение 2↔4 сессий не должно терять
   найденные контексты (формат канона — решение task.md).
4. Заглушка `bench` снимается; `watch/cache/agent-check` остаются
   заглушками этапа 3.

## DoD (checklist)
- [ ] `use 27b-multi` без канона: попытки по лестнице 196608→163840→131072
      (flash-multi: 262144→229376→196608→163840→131072), каждая попытка
      в выводе и в журнале попыток (ступень, вердикт); успех → канон.
- [ ] Повторный use с существующим каноном: ровно ОДНА загрузка
      (зафиксированное значение), пере-перебора нет.
- [ ] `--no-probe`: WARN + канон/минимальная ступень, одна загрузка.
- [ ] `use flash-multi --sessions 4`: та же лестница на 4 сессии; канон
      пары (flash-multi,4) не затирает (flash-multi,2).
- [ ] Все ступени отказали: die, в выводе таблица попыток (ступень →
      причина) — «это тоже результат» (PLAN).
- [ ] `gfctl bench`: 3 прогона, wall + tok/s, сводка; мёртвый порт → rc≠0
      с подсказкой; фикстура не изменена (md5-гейт в батарее).
- [ ] Internal checks зелёные; регресс 1.1+1.2 цел (180+ ассертов).
- [ ] EXP-заготовки окна этапа 2 поставлены в очередь (EXP-005-faex,
      EXP-006-evo-probe) — НЕ исполняются (BLOCKED-EXTERNAL).

## Constraints and known traps
- Роли не делают ssh/podman — probe и bench тестируются через faux-bin
  (podman logs отдаёт фикстурный load_failed/сценарий по ступени; curl —
  детерминированные ответы bench).
- Худший случай probe flash = 94 с × 5 ступеней — логировать прогресс
  каждой попытки (печатать «ступень X: …», как wait_load уже делает).
- Канон 1.2 (`~/gufo/.env`) расширяется БЕЗ ломания (старый формат
  GFCTL_PROFILE/sessions/context должен продолжать читаться; миграция —
  если нужна, то автоматическая при первом use).
- Timeout загрузки при probe: wait_load 180 с (1.2) — для flash 94 с
  достаточно; admission-отказ движка приходит РАНЬШЕ (в лог, F13) —
  ранний выход на load_failed (20 с, решено в 1.2) — переиспользовать.
- bench на 2 сессиях может делить движок — протокол: одиночный запрос,
  декод-токены из usage; НЕ параллелить (парный замер — EXP-004-стиль,
  отдельная история).
- python3 stdlib only; без IP/хостов; GNU-машины.
