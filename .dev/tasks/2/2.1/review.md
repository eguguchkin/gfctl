## Blocking

Нет. Ни одного пункта ниже порога блокировки: DoD 8/8 доказан (код + батарея + мой независимый прогон), ключевые инварианты Design подтверждены в коде (см. ниже), регресс цел, hygiene чистая.

**Инварианты Design (сверка по коду, все подтверждены):**
- *Канон не пишется до успеха probe*: попытки = `GFCTL_SESSIONS=… GFCTL_CONTEXT=… container_up` (commands.sh:469) — env-оверрайд поверх canon_get (env > .env); `write_canon` зовётся только из cmd_use ПОСЛЕ успеха (572); при полном отказе .env не тронут (§28, cmp байт-в-байт) — свойство отката живо.
- *Успех без второго recreate, serve_args при оверрайде == канонному*: `serve_args` — чистая функция (таблица + sessions/context аргументами, serve.sh:34–54); env-оверрайд отдаёт canon_get'у те же значения, которые затем пишет write_canon → байт-в-байт равен; cmd_use на probe-пути пропускает container_up (573–575). §26 «РОВНО 2 run» — PASS.
- *pairs изоляция 2↔4*: см. DoD 4.
- *fallback-чтение 1.2-формата*: `canon_pair_context` (state.sh:95–98) — GFCTL_PROFILE+GFCTL_SESSIONS совпали с парой → GFCTL_CONTEXT; чужие пары → пусто (→ probe). §14 PASS.
- *Атомарность write_canon*: render → `.env.tmp` → допись пар-блока → `mv -f` в том же каталоге (state.sh:156–161); единственный писатель сохранён.

- *full-refusal → таблица попыток*: см. DoD 5.

**Сверка ролей после 13ff56f:** `git diff 13ff56f` = только `.dev/STATE.md` (+ untracked: два EXP-скрипта, test-report.md) — код ролами после коммита не менялся. STATE/history — оркестратор, как положено.

## Non-critical notes (backlog)

1. **Триаж замечания tester'а №1 (MTP-симлинк): tester прав по коду, но правка EXP-005 НЕ требуется.** Проверено: таблица `set_flash` хранит ПЛОСКОЕ имя `mtp-…-shared-Q8_0.gguf` (models.sh:23), `ensure_weights` статит `$dir/$f` без подкаталога (models.sh:173,182), `serve_args` подставляет `@MTP@ → /models/<имя>` (serve.sh:47). Инструкция оркестратора «→ flash/MTP/» была ошибочной, однако EXP-005 как поставлен в очередь УЖЕ линкует плоско (`ln -sfn … "$FLASH_DIR/mtp-…gguf"`, строка 109) с разъясняющим комментарием в шапке (строки 19–22). **Статус: blocking-for-EXP снят — скрипт корректен как есть; единственное действие: НЕ «исправлять» строку 109 обратно в flash/MTP/ при подготовке окна.** Страховка механическая: SKIP×5 — PASS-критерий №1, неверный путь всплыл бы попыткой качать 2.79 GB.
2. **Триаж замечания tester'а №2 (admission-цифры промежуточных ступеней теряются): non-critical, backlog.** Код подтверждает: каждая следующая попытка начинается с `podman rm -f` (serve.sh:131) — логи отказавшей ступени стираются; журнал probe хранит вердикты (ступень → причина), не цифры. Это НЕ ломает DoD 2.1 (таблица «ступень → причина» — ровно то, что зафиксировал task.md §2, ратифицированный оркестратором). PLAN-DoD «отказ с цифрами admission-лога» — требует окна, и оба EXP снимают цифры отдельной явной попыткой верхней ступени ДО probe (EXP-005 строки 123–129: `use flash-multi --context 262144` + `podman logs | tail -40`). Предложение tester'а (писать хвост лога отказавшей ступени в журнал probe) — в бэклог как улучшение диагностичности прод-кода.
3. Последняя отказавшая попытка probe оставляет контейнер (не-загрузившийся) живым до выхода/die — следующий use/on его пересоздаёт (rm+run), вотчдог поднимет прежний канон. Безвредно, однопользовательский CLI; фиксировать не нужно.
4. Fallback `bench_request` срабатывает на каждом из 4 запросов независимо (худший случай 8 curl) — осознанный выбор dev-report (изоляция транспорта); при живом подтверждении `/v1/completions` на gufo после EXP-005/006 можно кэшировать эндпоинт (backlog, мелочь).
5. §32 батареи поднимает фоновый python-listener на 60 с — гасится kill в конце секции; при зависании батареи процесс умрёт по таймауту сам. Не дефект.
