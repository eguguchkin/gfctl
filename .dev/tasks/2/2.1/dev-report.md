## Fix round 2.1-F1 (2026-11-17): stat -L в SKIP-проверке download_file

**Триггер:** живой прогон EXP-005-faex (che-FAEX1, веса симлинками) — download_file не засчитал симлинки, начал перекачку (утекло 3.4 GB докачки до остановки окна).

### What was done

- **lib/models.sh, `download_file`, SKIP-проверка (root cause, одна строка):** `stat -c %s "$dest"` → `stat -L -c %s "$dest"`. GNU stat без `-L` не разыменовывает симлинк: возвращал размер ссылки (~91 B) ≠ пин → сравнение ложно → докачка; при этом `[ -f ]` симлинку следует (несимметрия). curl+mv поверх dest заодно заменял симлинк обычным файлом (данные не терялись — исходник в другом месте, но поведение неверно). С `-L` SKIP считает размер целевого файла и не качает — симлинк сохраняется.
- **lib/models.sh, докстринг `download_file`:** «Ограничения/допущения» дополнены одной строкой про `stat -L` и EXP-005-faex (почему).
- **tests/run_checks.sh, секция 9, +2 ассерта (218 → 220):**
  - позитив: tmp dest = симлинк на файл пин-размера → «SKIP:» + rc 0 + `[ -L ]` после вызова (симлинк не заменён);
  - негатив: симлинк на файл НЕпин-размера → НЕ SKIP, докачка PASS (sha OK), dest — уже обычный файл с верными байтами.

## Fix round 2.1-F3 (2026-11-17): ROUTE_MODEL обрезался по пробелу → 404 model_not_found

**Триггер:** живой факт EXP-005 (FAEX): gufo регистрирует flash-модель как `Qwen3.8 Flash Next` — С ПРОБЕЛАМИ (load_completed `model=Qwen3.8 Flash Next sessions=2 …`; /v1/models подтверждает id). Смоук получил 404 model_not_found: старый парсинг `grep -oE 'model=[^ ]+'` отрезал имя по первому пробелу → в запрос уходило `"model":"Qwen3.8"`.

### What was done

- **lib/health.sh, `parse_route` (root cause, одна строка):** `ROUTE_MODEL` = подстрока между `model=` и ` sessions=`: `sed -n 's/.*model=//p' | sed 's/sessions=.*//; s/[[:space:]]*$//'`. Флаг `s///p` печатает ТОЛЬКО при совпадении `model=` → нет совпадения ⇒ `''` (контракт «пусто → ROUTE_MODEL=''» сохранён; sed rc 0 всегда — `|| true` больше не нужен). Жадный `.*` берёт последнее вхождение `model=` (= старое «tail -n 1»); имя с пробелами приходит целиком; sessions= присутствует в load_completed всегда (F5/F17, лог EXP-005: `… model=Qwen3.8 Flash Next sessions=2 context_tokens=262144 speculative=mtp …`). Комментарий-«почему» в коде + дополнены докстринг `parse_route` и шапка модуля.
- **bench-путь проверен, правки НЕ требует:** `cmd_bench` строит тело запроса из того же `$ROUTE_MODEL` (lib/commands.sh:708, `python3 - "$fixture" "$ROUTE_MODEL"` → `"model": sys.argv[2]`); `bench_request` транспортует готовое тело без своего источника имени. Bench и smoke шлют ОДНО имя — чинится парсингом автоматически.
- **tests/run_checks.sh, §19 (health), +3 ассерта (222 → 225):** фикстура `LOGSP` — реальная форма строки FAEX (loader event=load_completed kind=text … model=Qwen3.8 Flash Next sessions=2 …): (1) `parse_route` на `LOGSP` → `[Qwen3.8 Flash Next|mtp|2|262144]` — имя целиком; (2) негатив-совместимость: старое имя без пробелов (`model=…pure sessions=1 …` в середине строки) парсится целиком; (3) smoke поверх `LOGSP`: SMOKE OK, ровно 3 curl-вызова, faux-лог curl содержит `"model":"Qwen3.8 Flash Next"` (полное имя в JSON; bench шлёт тот же ROUTE_MODEL).

## Fix round 2.1-F4 (2026-11-18): тихое урезание контекста движком (probe писал бы ЗАКАЗ) + smoke ретрай только первого

**Триггер:** два живых факта EXP-006 (evo). (1) probe-ступень заказала 196608, но load_completed пришёл `context_tokens=163840` (gpu 53/65 GiB, host_available 13.5 — машина нагрета; РАНЕЕ на чистой машине 196608 поднимался): gufo при нехватке места под RAM-cache ТИХО урезает контекст (явный отказ — только при полном «0 MiB», F13/F20). `probe_context` считал бы ступень успешной и записал бы в канон ЗАКАЗАННЫЕ 196608 — ложь (сервер на 163840). (2) смоук упал FATAL на пустом ВТОРОМ ответе — ретрай (F15) покрывал только первый запрос.

### What was done

- **lib/commands.sh, `probe_context` — сверка факта с заказом (root cause):** после `wait_load 180` rc 0 факт берётся из `ROUTE_CTX` (заполнен последним `parse_route` внутри wait_load, второго чтения лога не нужно). Факт ≠ заказ → `probe_log "ступень N: движок поднял фактический M — принимаю факт"` (обе цифры в журнале) + `warn` в stderr → `PROBE_CTX=$M` (канон = ФАКТ) → `return 0`: БОЛЬШИЕ ступени лестницы не продолжаются (факт = фактический максимум при данном состоянии машины), меньшие не нужны — стоп после факта. Случай факт > заказ невозможен, но ветка симметрична — факт принимается без сравнения направлений. Пустой `ROUTE_CTX` (load_completed без context_tokens — форматом не наблюдается) → прежнее поведение (заказ). Докстринги `probe_context`/`cmd_use` синхронизированы.

Семантика провала прежняя: после второй пустой `ok=0`, die в конце (оставшиеся промпты прогоняются — «как сейчас»).
