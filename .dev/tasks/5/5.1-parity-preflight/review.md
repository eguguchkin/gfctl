## Non-critical notes (backlog / окно)

1. **memlock-гейт на use-пути: sudo tee при КАЖДОМ вызове на машинах с ml ≥
   8388608, но конечным** (FAEX: 1318060032 kB) — ветка «≥ порога» вызывает
   `ml_write` (унаследовано байт-в-байт из 4.1-F2 «файл во всех ветках — ради
   будущих relogin»). Это противоречит двум формулировкам контракта: коммент
   preflight_host «Оба вызова (install/use) на установленной машине = полный
   no-op без sudo» и task.md Risks «На FAEX/evo ожидался полный no-op». Для
   install поведение прежнее; новым оно стало только на use. Где что: батарея
   это не видит (шим `ulimit→unlimited` уводит в PASS-ветку без записи). Не
   блокер: директор «байт-в-байт» ратифицирован, отказ sudo громкий (set -e),
   пререквизиты EXP-014/015 уже требуют «sudo без пароля или интерактивный
   запуск». Рекомендация окну: держать sudo-кэш тёплым в recreate-цикле
   EXP-015 (там `use --no-probe` гоняется многократно) и поправить
   формулировку «полный no-op без sudo» при следующей ревизии SPEC/коммента.
2. Текст memlock-WARN на use-пути отсылает «повтори gfctl install» — задокументировано
   в dev-report (байт-в-байт победил косметику). Принято; можно переформулировать
   при следующей ревизии текстов (не байт-в-байт-критично).
3. task.md Round 2 буллет «успех → log-строка + счётчик» vs код (инкремент ДО
   delete-container) — неточность буквы буллета; код 1:1 с hfctl = ратифицированная
   директива. Уже отмечено тестером; соглашаюсь.
4. Экзотика «клон без tpl, но с leftover .gfctl-containers.conf»: bootstrap не
   пересоздаст (нет источника), но export-гвард заскопит устаревший файл.
   Задокументировано в коде как тихий пропуск; реальный риск ~0 (tpl есть во
   всех клонов). К сведению.
5. EXP-015 завершается состоянием «gfctl off» (машина на hfctl-проде) — соответствует
   правилу окон (прод восстановлен); итоговые состояния стеков стоит явно
